# AgentVane 参考细则（随技能携带）

> 本文件在 `skills/agentvane/` 内，**随 SKILL.md 一起复制/安装**，独立安装时也在。核心纪律见 `SKILL.md`，这里是可照抄的模板与细则。

---

## 一、台账模板

### WORKLOG 条目（大/中改动，加在顶部）
```
## YYYY-MM-DD 任务标题（#编号）
- **目标** / **验收标准** / **排除项** / **方案** / **回退点**
- **改动** / **验证**（边做边补）
- **状态**：进行中   **待办**：
```

### BUG_LEDGER 条目（每遇 bug 当场加一行）
```
| # | 现象 | 根因 | 防御规则 |
```

### 冷启动
新项目无台账 → `WORKLOG.md` / `BUG_LEDGER.md` 各建一个，顶部放索引区（后续条目标题 + #号 + 日期 + 归档去向），再从索引下方开始写条目。

### 归档
主文件只留最近 30–50 条；更早的按月搬到 `WORKLOG-archive-YYYYMM.md` / `BUG_LEDGER-archive-YYYYMM.md`，主文件顶部留索引指向归档。

## 二、真实验证 —— 命令与判断（通用）

- **静态**：`go vet ./...` / ESLint / 对应语言 lint。
- **单测/集成**：`go test ./...`（关键路径 `-race`）；跑相关包/文件。
- **真实链路**：真实 provider API 端到端（如 `go test -run TestE2E... -v`），不依赖 mock。
- **构建/打包**：前端 `npm build` → 桌面 `wails build`（**禁用 `-clean`**，会清空产物删掉安装包）。失败逐层看日志（如 wails build 日志 → npm build 日志）。
- **真机验证**：涉 UI/运行时，打包后必须用户真机测试通过才提交；交付前核对产物时间戳 + 提示彻底退出旧进程。
- **UI 几何验证**：用 `getBoundingClientRect` + 像素扫描（非单元素 display/width）；视觉模型只作参考。

### 交付前 5 分钟验收清单（导入/存储/持久化类）
1. 正向：标准合规文件导入，界面正常。
2. 边界：空 JSON / 空数组 JSON。
3. 异常：损坏 JSON、缺字段旧版、带 BOM。
4. 持久化：导入 → 关 → 重开 → 数据在。
> 铁律：`解析没报错` ≠ `读到有效条目`；条目 0 必须主动报错，禁止静默"导入完成"。

## 三、上下文与文件体积管理（细则）

- 只读**顶部索引 + 最近 ≤10 条 + 相关条目**；查历史用 grep（按 #号/功能/现象词），命中只读该块。
- 主文件只留最近 30–50 条；旧条目按月归档；每条台账 3–6 行，禁止整段 dump 代码/日志。
- **自动注入面要小**：`AGENTS.md` 只放核心（一页内）；细则放按需参考文件；用"摘要 + 指针"而非整篇塞进上下文。
- 触发词要窄：流程纪律只管流程；具体排障交给窄触发的小技能（如 `windows-gotchas`）。

## 四、常见坑速查（通用跨语言）

- 改了"没生效"：核对产物/进程版本 + 数据目录；配置/语言包磁盘优先，改后必递增版本号。
- 工具/截图故障**禁止死磕**：终止 → 记台账 → 查资料 → 有边界修（2 次定位，失败即停）。
- PowerShell 多行/命令链：不支持 heredoc/`&&`；多行 body 写文件再 `git commit -F`，提交后 `git log --oneline -2`+`git status --short` 验证。
- 字节 vs 字符：截断统一用 **字符计数**（Go 用 `[]rune`），别用字节长度切片。
- 返回 slice/map 的方法：nil 转空容器；模板侧访问 `.length`/字段要防御。
